# Content plan：Category → Bucket → Cluster → Pillar 點分、邊個先

你講嘅「第一個 step 揀 categories」係啱嘅。後面三個詞好易撞車，因為人人定義唔同。COLOURLIVING 用下面呢套即可——**四層，一層細過一層，每層只做一件事。**

```
生意揀 Category（賣咩／想要邊類詢盤）
        ↓
   內容定 Bucket（90 日只打 2–3 個主題桶）
        ↓
 搜尋整理 Cluster（一堆近義搜尋詞 → 一個正規 URL）
        ↓
   寫作做 Pillar（一篇長文／一個強頁，贏嗰個問題）
        ↓
  短文、產品、FAQ 都連返 pillar 同 collection
```

**唔好**一開始開十個 blog category，亦唔好一張 Excel 五千個 keyword 先寫。

---

## 四層分別（用 Gessi 浴室做一條線）

| 層 | 係咩 | 唔係咩 | COLOURLIVING 例子 |
| --- | --- | --- | --- |
| **Category** | 生意分類：舖頭賣咩、想多邊類客人 | 唔係 SEO 詞表 | 浴室龍頭（先過燈飾） |
| **Bucket** | 內容主題桶：90 日 blog／指南只打呢 2–3 個方向 | 唔係 Shopify collection、唔係 blog category | 「邊度買歐洲品牌」 |
| **Cluster** | 一組 **同一意圖** 的搜尋詞，共用 **一個** 正規頁 | 唔係一篇文；唔係一個 tag | `gessi hong kong`、`gessi 龍頭`、`gessi tap hong kong` → 正規頁 `/collections/gessi` |
| **Pillar** | 一篇（或一個）**完整答嗰個問題** 的頁 | 唔係產品卡、唔係 300 字 EDM | Journal：*Where to buy Gessi taps in Hong Kong*，開頭就答灣仔可睇、預約、只送香港，內連 Gessi collection |

一句：

- Category = **賣咩**  
- Bucket = **今季講咩主題**  
- Cluster = **人點搜、邊頁收**  
- Pillar = **寫一篇去贏呢個問題**

---

## 點解要拆四層（唔係為咗好聽）

**1. Category 先：否則內容同貨盤唔對。**  
寫「智能家居」但舖頭唔賣，Google 排到都轉唔到預約。先揀有合約、有陳列、90 日想要詢盤的類（例如浴室龍頭、B&B、梳化），先至談內容。

**2. Bucket 收窄：否則 Journal 會變成雜誌。**  
Luxury 每人每週寫唔到十篇。三個桶（邊度買／點樣選香港單位／到店同設計師）先至決定「呢 90 日 *唔寫* 乜」。Bucket 係 **拒絕清單**，唔係 SEO 技術。

**3. Cluster 對 URL：否則同一題開十頁互搶。**  
`gessi hong kong` 同 `gessi 香港` 不應該一篇 blog、一個 collection、一個 About 各打各的。Cluster 規定：**一個意圖 = 一個正規 URL**。Collection 贏「邊度買 Gessi」；pillar 文章贏「點樣喺香港指定 Gessi／點去睇」並 **連返** collection。產品頁贏型號。

**4. Pillar 先於短文：否則永遠得碎片。**  
Google／AI 要一篇 **完整答案**（地址、邊度睇、連去貨、預約）。短訊、IG、EDM 再從 pillar 拆。冇 pillar 就噴短文 = 冇頁可以排、AI 冇文可抄。

## 先後次序（每次制定計劃都跟）

### Step 1 — Categories（生意，1 頁紙）

寫低最多 **三個** 90 日優先：

例：① 浴室龍頭 ② B&B／梳化 ③ 到店預約（本地）

燈飾若而家唔係主攻，整桶 P1，唔寫入今季 Journal。

對照舖頭：有冇貨、有冇樣板、可唔可以公開講 retailer。

### Step 2 — Buckets（內容範圍，仍然唔搜 keyword）

把 Step 1 收成 **2–3 個內容桶**：

| 桶 | 對應 Category | 今季寫唔寫 |
| --- | --- | --- |
| 品牌／邊度買 | Gessi、B&B、Dornbracht… | 寫 |
| 品類點揀（香港單位） | 梳化呎吋、獨立浴缸、恆溫龍頭 | 寫 |
| 到店／項目 | Showroom、設計師 FF&E | 寫 |
| 燈飾、廚房、生活雜文 | — | **今季唔寫** |

呢步結束：**仲未開 Shopify blog category。**

### Step 3 — Clusters（搜尋詞歸堆，指定正規頁）

打開 [keyword-clusters.md](keyword-clusters.md)。每個 cluster 問：

- 人搜呢堆詞時，**想去邊頁**？
- 嗰頁 **而家有冇**？（Gessi collection 有就用；冇就先建品牌頁，唔好先寫 blog）

規則：

| 意圖 | 正規頁（通常） | Pillar 角色 |
| --- | --- | --- |
| 品牌 + 香港（gessi hong kong） | `/collections/gessi` | 文章支援，內連 collection |
| 品類（designer sofa hong kong） | `/collections/sofa` | 指南 pillar 連 sofa |
| 型號（Alys LY153） | `/products/...` | **唔使** pillar |
| 本地（灣仔傢俬） | Showroom／About | 一篇到店 pillar |

一個 cluster **唔好** 兩個正規 URL。輔助詞放該頁 H2／FAQ，唔好另開頁。

### Step 4 — Pillars（12 條題，90 日只承諾 6 篇）

每個 bucket 抽 2–4 條 **問題句** 當 H1。每條 pillar 必須：

- 對準 **一個** cluster 的主詞  
- 連去 **一個已存在** 的 collection／About  
- 開頭 40–80 字就答（邊度、地址、預約、只送香港）

例（浴室桶）：

- Cluster「Gessi 香港」→ Pillar《Gessi taps in Hong Kong》→ 連 `/collections/gessi`  
- Cluster「浴室龍頭品類」→ Pillar《歐洲龍頭點樣配香港浴室翻新》→ 連 faucet collection  

產品頁 **唔算** pillar。品牌 collection 文案加強 = 半個 pillar（好多時 ROI 高過 blog）。

### Step 5 — 先至開 Journal 結構

一個 blog、8–10 個 tags。Tags ≈ bucket／品牌名，**唔係** 再開一層 cluster。每篇最多 2–3 個 tag。

之後先寫 Brief → 寫文 → 內連。見 [blog-content-sop.md](blog-content-sop.md)。

## 互相點用（應用關係）

```
Category 浴室龍頭
  └─ Bucket「邊度買歐洲浴室品牌」
        └─ Cluster 3：gessi hong kong / gessi 龍頭 / gessi 香港
              ├─ 正規頁：/collections/gessi     ←  fortify 答案段、H1
              ├─ Pillar：Journal 一篇「香港邊度買 Gessi」
              └─ 支援：2 個產品 PDP、FAQ 兩條、IG 一則（全部連返 collection 或 pillar）
        └─ Cluster 6：bathroom faucet hong kong
              ├─ 正規頁：/collections/bathroom-faucets
              └─ Pillar：龍頭點揀指南
```

- **Collection** 贏目錄意圖（「Gessi 香港」想睇貨）。  
- **Pillar** 贏問題意圖（「邊度買／點樣選／可唔可以去灣仔睇」）。  
- **Cluster** 保證兩頁唔互搶：主詞歸 collection 定 pillar 要寫死；另一頁用內連，唔用同一個 H1。  
- **Bucket** 保證你今季唔會突然寫 Flos 十篇而 Gessi 零篇。  
- **Category** 保證寫完有貨、有人接 WhatsApp。

典型錯法：

| 錯 | 點解衰 |
| --- | --- |
| 先開 15 個 blog category | Category／bucket 未定，空欄互搶 |
| Cluster 當一篇文 | 十個近義詞開十頁 |
| Pillar 唔連 collection | Google 唔知文章同貨盤係同一間店 |
| 只寫產品、唔做 cluster | 型號頁贏唔到「Gessi 香港」 |
| 只寫 pillar、collection 空白 | 文章排到，落地冇貨 |

## 90 日最小可行計劃（照填）

1. Categories：______ / ______ / ______  
2. Buckets：______ / ______ / ______  
3. 每個 bucket 揀 **2 個** 已有 collection 的 cluster  
4. 每個 cluster 一篇 pillar H1 + 一個正規 URL  
5. 先改 **collection 答案段**（好多時快過寫 blog），再寫 pillar  
6. 每月 1–2 篇 pillar，唔好灌水
